# 计算器

一个用 Python 标准库写的桌面计算器。单文件、零第三方依赖，跑起来就一个窗口。

## 运行

```bash
python3 calculator.py
```

需要 Python 3.9 或更高版本，且自带的 tkinter 可用（macOS 官方的 python.org 安装包默认带）。

## 自检

不带图形界面也能验证核心逻辑：

```bash
python3 calculator.py --selftest   # 求值器测试，28 项
python3 calculator.py --smoke      # 构建窗口 + 按键状态机测试，10 项，跑完即退
```

`--selftest` 覆盖正常计算和 10 种错误输入；`--smoke` 会在真实窗口里模拟一串按键序列，验证输入状态机（连按运算符、除零、结果后续算等）。两个都返回退出码 0/1，可以挂到 CI 上。

## 功能

- 四则运算，支持括号嵌套和运算优先级
- 一元正负号、后缀百分号（`200 × 10 % =` 得 `20`）
- 鼠标点击和键盘输入两套操作，共用同一套逻辑
- 错误提示具体到原因，不是笼统的 "Error"

## 键盘快捷键

| 按键 | 作用 |
| --- | --- |
| `0`–`9` `.` | 输入数字 |
| `+` `-` `*` `/` | 运算符 |
| `(` `)` | 括号 |
| `%` | 百分号 |
| `Enter` | 计算 |
| `Backspace` | 退格 |
| `Esc` / `Delete` | 清空 |

## 设计上的两个取舍

### 求值器是手写的，没有用 `eval()`

`eval()` 版计算器写起来只要三行，代价是给机器开了个任意代码执行的口子——往输入框里塞一句 `__import__('os').system(...)` 就完事了。这里换成了一个四层递归下降解析器：

```
expr    := term (('+' | '-') term)*
term    := unary (('*' | '/') unary)*
unary   := ('+' | '-') unary | postfix
postfix := primary '%'*
primary := NUMBER | '(' expr ')'
```

多了几十行代码，换来的是"输入什么都不会被执行"。

### 按钮是自绘的，没用 `tk.Button`

macOS 的 aqua 主题会直接忽略 `tk.Button` 的 `bg` 参数——你设深色，它照样给你画浅灰，整套配色当场作废。所以按钮是用 `tk.Frame` + `tk.Label` 加鼠标事件自己拼的，悬停和按下的反馈也自己控，三个平台表现一致。

## 已知限制

- 不支持幂运算、三角函数、对数。
- `±` 作用在 `5-3` 上会得到 `5--3`，数学上等于 `5-(-3)=8` 没错，但显示出来确实绕。做 AST 级改写才能更聪明，暂时不值这个复杂度。
- 结果统一保留 12 位有效数字，超出范围会显示成科学计数法。拿来算钱的话别指望它替你做财务级舍入。
- 输入长度上限 30 个字符。
- 按键是直角，因为 tkinter 没有原生圆角。要圆角得改用 `tk.Canvas` 逐个绘制。
